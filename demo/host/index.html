Maintainer's Copilot — Demo Host Page

This page simulates an external website that has embedded the Maintainer's Copilot chat widget. The chat bubble appears in the bottom-right corner once the backend is running and a valid widget ID is set.

Before opening this page:
  1. Start the stack: docker compose up -d (builds the widget bundle inside the widget image).
  2. Open the Streamlit AI Ops Control Center at http://localhost:8501, log in as an admin, go to Widget Manager, and create a widget config. Copy the public_widget_id UUID.
  3. In that widget config, set Allowed origins to include both http://localhost:3000 (the widget iframe fetches its config from this origin) and http://localhost:8080 (this host page, allowed to frame the widget via CSP).
  4. Open this page with the id in the URL: http://localhost:8080/?widget_id=YOUR-PUBLIC-WIDGET-ID. The id is remembered in localStorage, so subsequent visits to http://localhost:8080 reuse it.

Streamlit vs widget: Streamlit is the internal AI Ops Control Center (maintainer/admin tooling). This bottom-right bubble is the production-shaped embeddable React widget — the surface a real website would ship.

Simulated page content

This is a typical host page. The Maintainer's Copilot chat widget floats in the bottom-right corner. Click the bubble to expand the chat panel.

The widget fetches its configuration (greeting, theme, enabled tools) from GET /api/v1/widgets/{public_widget_id} at load time and calls POST /api/v1/chat for every user message.

How embedding works

Paste one <script> tag anywhere in your page's <body>. The loader script at /widget.js:

  1. Reads data-widget-id and data-api-base-url from the tag.
  2. Creates an <iframe> pointing to the React widget app (/widget-app/).
  3. Listens for postMessage events from the widget to resize the iframe when the user opens or closes the chat panel.
  4. Keeps widget CSS and JavaScript isolated from the host page via the iframe boundary.

Embed snippet

A real site pastes one <script> tag with its own data-widget-id. This demo instead resolves the id at runtime from ?widget_id= or localStorage so you can swap configs without editing files: 

<script
  src="http://localhost:8000/widget.js"
  data-widget-id="YOUR-PUBLIC-WIDGET-ID"
  data-api-base-url="http://localhost:8000"
  data-widget-url="http://localhost:3000/widget-app/"
></script>
